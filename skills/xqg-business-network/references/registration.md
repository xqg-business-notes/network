# 确认档案、保存编号与微信开放匹配

## 用户确认前

读取 profile-card.md，以用户自愿提供的资料整理卡片。展示准确的本人完整卡片和脱敏公开预览，说明确认后保存到数据库、经小强哥微信确认后才开放匹配。用户明确确认后才能提交。演练不提交；只确认措辞但明确拒绝保存时不提交。不从同名候选认领档案。

## 正式登记

status 的 registration_available=true 表示支持。没有该能力时不调用未知接口、不声称已保存，保留微信人工登记路径。

先运行 `network_client.py my-profile` 读取当前连接已登记的本人档案；只返回本连接绑定资料，不按用户报出的别人的编号覆盖。已有档案沿用原编号；新设备没有本人旧档案时，请小强哥核对编号与身份，不能凭编号自行接管。当前访问标识不是实名证明。

将已确认的内容写入仅本人可读的临时JSON文件（权限0600），字段严格如下。只取已确认可用于匹配的信息，缺失列表用[]，称呼必需，无姓名时询问希望展示的称呼；不得补造。正式存储不把微信号和私人联系方式写进这份供查询匹配的档案。

```json
{"name":"本人确认的称呼","cities":[],"companies":[],"businesses":[],"resources":[],"needs":[]}
```

至少有业务、资源或需求之一。城市、公司和业务各最多5项，每项400字；资源和需求共最多6项，每项800字。提交整体超长时先精简给本人重新确认，不静默截断。来源文件不是自动公开的全部内容，不上传原始附件或无关数据。

提交前用同一份待确认JSON运行 `python3 scripts/preview_profile.py --file 私有JSON文件`，在聊天里展示返回内容的易读预览，注明“别人会看到的样子”。该步骤只在本机执行。称呼加星号、公司等字段按用户的展示意愿处理；不愿展示的内容从提交JSON中移除，再生成预览。此版本没有独立的私密业务字段，不可承诺“提交但不公开某个业务字段”。本人卡片中的真实称呼用于后台引荐，公开预览使用脱敏称呼。公司名及业务组合仍可能让熟人识别本人，不把姓名遮盖称为完全匿名。用户同时确认内容和展示范围后提交；已经确认了这两项无需重复问。

生成一个新的随机提交ID（16–80位字母数字、下划线或短横线），执行：

```text
network_client.py register-profile --file 私有JSON文件 --id 提交ID --confirmed
```

重试必须使用同一个ID与相同内容，最多一次可恢复重试；失败不换ID绕过。改动后的档案重新给本人确认，使用新提交ID，但后台沿用原A编号。发生平台审批拒绝时遵守宿主审批，不换工具绕过。

只有回执包含 saved=true、registered=true 和正式 person_id 才能报告已入库。将真实编号写入完整确认版，再展示可复制正文。replayed=true 的回执是原提交的历史结果；若不是紧邻的失败重试或已有后续修改，先用 my-profile 核对当前版本，不以旧回执覆盖新版本。

默认回执 registration_status=pending_wechat、matching_open=false。提醒添加小强哥微信并把整张档案发给他，说明微信确认后开放匹配。不要把 conversation_turn 或 profile_summary 的保存回执当登记成功。正式档案不是90天聊天日志，不因接待记录过期被删除。

## 微信与开放匹配

用户说“已加微信”可以提醒发送完整档案，但不能自行视为管理员已确认或开放匹配。小强哥通过管理员通道确认身份、可微信联系到本人后，由管理员检查当前档案版本并开放匹配。公开客户端无此权限，不提供管理命令。

查询 my-profile 的 matching_open=true 才能说已开放匹配；尚待确认则准确报告。已经加微信的用户无需反复添加，直接发送当前完整档案。档案更新重新确认保存后，先退出公开匹配，交小强哥核对该版本再开放；沿用编号。

停止聊天记录不等于拒绝正式登记；两者独立，仍须本次明确确认保存档案。不能因停止聊天记录而强制用户重新开启。登记不自动拉群或发送微信消息。
